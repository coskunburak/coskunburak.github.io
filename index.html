MocapExpo

⭐ Thesis / Pipeline Architecture

End-to-end motion capture pipeline. React Native client records video, streams to S3 via signed URLs. A Fastify backend dispatches GPU jobs to RunPod Serverless where a Python worker runs WHAM/SMPL pose estimation and DLT triangulation. Built with strict no-fake-success invariants.

TypeScriptReact NativeNode.js / FastifyWHAM / SMPLRunPod Serverless
System Architecture Flow MOBILE (React Native) │ Creates: Project → Take → CaptureSession ▼ Multipart upload via pre-signed URL AWS S3 / MINIO ▼ Webhook / Polling BACKEND API (Node/Fastify) │ Persists job state in PostgreSQL ▼ REST Dispatch RUNPOD WORKER (GPU / PyTorch) IF Single Camera: ↳ WHAM Solve → SMPL Model → optimized_result.bvh IF Dual Camera: ↳ 2D Pose Extraction (Camera A & B) ↳ Timestamp Sync & Intrinsics Calibration ↳ DLT Triangulation (3D Landmark Cloud) ↳ Reprojection Error Gate (Must pass P95 threshold) RETURN finalAnimationSource: "true_dual_solve" | "primary_wham"

Key Engineering Decisions

  • Serverless GPU: Chose RunPod over EC2 to eliminate idle costs while retaining heavy PyTorch inference capabilities.
  • Direct S3 Uploads: Backend issues signed URLs. Node.js never proxies video bytes, saving massive bandwidth and memory.
  • No Fake Success: Dual-camera solves produce 10+ QA metrics. If reprojection error is too high, it fails explicitly rather than returning bad data.

Interview Highlights

  • I built the entire stack solo: the mobile app, the backend orchestrator, and the Python GPU worker.
  • Security focus: Machine learning assets (WHAM/SMPL models) are excluded from the git repo and distributed securely via 1Password CLI in CI.
  • The system is resilient: failure in the dual-camera diagnostic path gracefully degrades to the primary WHAM solve, clearly documented in the API response.

Verified AI

Production AI Platform

iOS-first mathematics platform. Swift/SwiftUI client backed by a Java 21 Spring Boot modular monolith. It orchestrates provider-neutral LLMs and programmatically verifies every AI-generated math solution using a deterministic SymPy (Python) engine.

Java 21 / Spring BootSwiftUISymPyModular MonolithPostgreSQL
Trust & Verification Architecture iOS CLIENT → Sends raw math problem (Image/Text) ↓ SPRING BOOT MONOLITH (AI Orchestration Module) │ Port/Adapter pattern for LLM Providers → call Gemini/GPT-4o → Returns UNTRUSTED solution steps ↓ SPRING BOOT (Verification Module) │ Business invariant: AI output cannot be marked VERIFIED internally. → call INTERNAL MATH VERIFIER (FastAPI + Python SymPy) ↳ Parses algebraic expressions ↳ Executes deterministic symbolic computation RETURN VERIFIED | FAILED | CANNOT_VERIFY ↓ iOS CLIENT ← Displays solution ONLY with backend-authoritative verification badge

System Invariants (ADRs)

  • ADR-002 (Modular Monolith): Chose strict module boundaries in Java over microservices to avoid distributed complexity while maintaining isolation.
  • ADR-004 (Separate Python Verifier): SymPy runs outside the JVM. The verifier is independently scalable and inaccessible from the public internet.
  • Backend Authoritative: iOS app holds zero entitlement or verification logic; everything is strictly server-driven.

Interview Highlights

  • I wrote 45+ canonical technical documents and 4 formal ADRs for this project, optimizing them for both human engineers and AI context (NotebookLM/Codex).
  • The AI routing is provider-neutral. Switching from Gemini to GPT-4o is a single adapter configuration change without touching business logic.
  • I specifically designed it so the iOS client can never directly contact the Python verifier, preventing prompt-injection attacks from bypassing the gateway.

GlowStudio AI

On-Device Machine Learning

Offline-first iOS portrait editor. A custom PyTorch face parsing model exported to Core ML runs entirely on-device. It generates segmentation masks (lips, skin, hair) used by custom Metal shaders and Core Image filters for real-time rendering.

Core Technical Feats

  • Zero 3rd-Party SDKs: App target relies purely on Apple frameworks (Vision, CoreML, Metal). Zero supply chain risk.
  • BeautyQA Visual Regression: Built a custom shell script + xcodebuild pipeline that runs the Core ML model on test images and asserts pixel-level IoU thresholds to catch visual regressions.
  • Strict Clean Architecture: Domain layer is pure Swift value types. It knows nothing about SwiftUI, Core Image, or StoreKit.

Interview Highlights

  • I trained the semantic segmentation model myself in PyTorch rather than relying on a paid Cloud Vision API, achieving zero latency and complete data privacy.
  • The entire app functions completely offline. The only network calls are for StoreKit 2 subscription validation.
  • The Clean Architecture implementation uses manual Dependency Injection (`AppDIContainer`), avoiding bloated 3rd-party DI frameworks.

Seyir Kiosk

🟢 Live Enterprise Production

Android kiosk management system deployed on physical corporate tablets. A React Native app utilizing a custom Java Native Module to lock the OS, override system navigation, manage WebView bridges, and accept remote configurations.

React NativeAndroid SDK / NDKDeviceAdminReceiverRemote Config

Kiosk Lock-Down Mechanisms

  • Device Admin API: React Native cannot lock an Android device alone. I wrote a Java Native Module that registers a `DeviceAdminReceiver` and calls `startLockTask()`.
  • System Overrides: Suppresses the BACK button at the Activity level and blocks the HOME intent entirely to prevent users from reaching the Android launcher.
  • JS ↔ Native Bridge: A custom `postMessage` WebView bridge allows the loaded web application to securely command the native Android hardware (brightness, volume, wake locks).

Interview Highlights

  • This isn't a prototype; it's currently live in a corporate environment managing physical tablet fleets.
  • I implemented `patch-package` combined with `npm ci` to ensure custom native module patches are 100% reproducible across CI/CD and developer machines.
  • The system architecture heavily leverages remote configuration, allowing UI/UX updates to the fleet without requiring physical ADB access or APK reinstalls.

Block Blast

Game State Engineering

iOS block puzzle game with 5 modes, meta-game economy, and StoreKit monetization. Architected around a pure, deterministic unidirectional state reducer, allowing full unit-testability of the game loop independent of the rendering engine.

SwiftUI / SpriteKitUnidirectional StateGame CenterFastlane CI/CD

Architecture & Determinism

  • Pure Reducer: `GameReducer.reduce(state: action)` has zero side effects and touches no storage. It takes a state, applies an action, and returns a new state.
  • UI Decoupling: The `GameScene` (SpriteKit) only registers touches and renders the state output. Zero game rules exist in the view layer.
  • Fairness via Seeds: The "Daily Seed Race" mode relies on the reducer's absolute determinism. A server-provided seed ensures identical RNG across all devices globally.

Interview Highlights

  • Because the core loop is a pure function, I can unit test complex multi-turn logic instantly without spinning up a simulator or mocking UI components.
  • I built a complete automated pipeline using Fastlane and GitHub Actions that runs preflight linters and unit tests before any beta build is allowed.
  • The monetization stack (Ads + IAP) is controlled via remote config feature flags, entirely decoupled from the core game state.
