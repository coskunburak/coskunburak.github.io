Engineering Decisions

  • RunPod Serverless — GPU compute on demand, no fixed infrastructure cost. Jobs dispatched via REST; worker pulls video from S3 directly.
  • S3 signed URLs — Backend never proxies video bytes. Mobile uploads directly to object storage; backend only issues time-limited presigned tokens.
  • Single-camera WHAM is always the production path — dual-camera data never overrides the primary solve unless all quality gates pass explicitly.
  • No fake success policy — missing_calibration, missing_sync, missing_pose_frames flags are explicit. System fails loudly with reason codes, never silently.
  • WHAM/SMPL assets not in repo — licensed models distributed via password manager (1Password/Bitwarden), not version control.
  • Docker Compose local stack — PostgreSQL + MinIO for development without any cloud dependency.

Dual-Camera Diagnostic Pipeline Detail

  • Per-camera 2D pose extraction — MediaPipe or WHAM 2D adapter, outputs pose_frames_device_N.json
  • Frame sync — timestamp matching across device clocks; reports averageTimeDeltaMs and syncConfidence
  • Camera calibration — fallback to known device intrinsics; real calibration via checkerboard/AprilTag (roadmap)
  • DLT triangulation — Direct Linear Transform for 3D landmark recovery from stereo 2D keypoints
  • Reprojection error gate — reprojectionErrorPx and reprojectionP95Px must be below threshold for dual solve to be accepted
  • Diagnostic-only flag — reconstruction may pass quality check but still be diagnostic-only; never becomes final animation unless all gates pass

Architecture Decision Records (ADRs)

  • ADR-001 — PostgreSQL over Firestore: Relational learning state, ACID guarantees, complex JOIN queries for mastery graph, no vendor lock-in, no per-read pricing.
  • ADR-002 — Modular Monolith over Microservices: Explicit module boundaries without distributed systems complexity. Each module has a defined contract; microservices can be extracted later if needed.
  • ADR-003 — Provider-Neutral AI: ModelRouter behind ports/adapters pattern. Swapping Gemini for GPT-4o is a single-module change. Prompt versioning is independent of provider.
  • ADR-004 — Separate Python Math Verifier: SymPy runs in Python outside JVM — independently deployable, independently scalable, mathematically deterministic by design.
Non-Negotiable System Invariant #1: AI output is untrusted input
AI-generated math solutions flow through the SymPy verifier before any VERIFIED status is assigned. The VerificationPolicy class is the only code path permitted to set verification status. This is enforced by module visibility — AI adapters cannot import the verification domain.
✓ Enforced at compile time via module boundaries
Non-Negotiable System Invariant #2: Backend authoritative for all gating
The iOS app holds no access-control logic. Free/Pro/Pro+ entitlement decisions are made exclusively by the Spring Boot API, which receives and validates StoreKit 2 server notifications. The iOS app presents whatever the server says the user can access.
✓ iOS app has no entitlement decision code
Non-Negotiable System Invariant #3: iOS never contacts the math verifier
The FastAPI/SymPy verifier is internal infrastructure. It is not exposed externally and has no public endpoint. All verification requests originate from the Spring Boot backend. This prevents prompt injection through the client and keeps verifier behaviour server-controlled.
✓ Verifier URL is not present anywhere in iOS codebase
Non-Negotiable System Invariant #4: Redis is disposable
Redis holds only cache data. Learning state, mastery scores, and skill records are always persisted to PostgreSQL. If Redis is wiped, the system recovers fully from PostgreSQL. No user-facing feature depends on Redis availability.
✓ All learning writes go to PostgreSQL first

Key Engineering Decisions

  • Zero third-party SDK dependencies in the app target. All frameworks are Apple-provided (Vision, Core ML, Metal, Core Image, StoreKit, PhotosUI, os.Logger). No CocoaPods, no SPM packages.
  • Offline-first by design — all ML inference, rendering, and editing runs on-device. No network required for any core feature.
  • Custom model, not a cloud API — face parsing uses a local .mlmodel file trained with PyTorch. No Roboflow, no cloud vision API. This eliminates latency, cost, and data privacy concerns.
  • Manual dependency injection — AppDIContainer creates all services at launch. No third-party DI framework. Dependencies are explicit and traceable.
  • Protocol-backed analytics and crash reporting — stubs behind protocols, ready to be replaced by live SDKs without touching feature code.
  • FeatureFlag.swift controls premium gating — intentionally relaxed during testing; must be reviewed before any production release.

Why GameReducer is Pure

  • No storage access inside GameReducer. It receives state, returns new state + events. Side effects (save, analytics, ads) happen in GameEngine after the reduce call.
  • This makes the entire game loop unit-testable without a device or simulator. You can test every rule, every edge case, every score calculation as a simple function call.
  • Deterministic: same sequence of GameActions always produces the same GameState. Daily Seed Race depends on this for fairness.
  • SaveGameStoreProtocol is a protocol — the test suite injects a mock. UserDefaults is only used in production.
  • GameScene only renders. It calls engine.dispatch(.placePiece(...)) and renders whatever GameState says. Zero game logic in the scene.

Key Technical Challenges Solved

  • Device Admin + Task Pinning — implementing kiosk lock-down in React Native requires a Java native module that calls startLockTask() and registers a DeviceAdminReceiver. Cannot be done from JS alone.
  • HOME button override — standard Android HOME always exits any app. Kiosk mode requires Device Admin privileges to block the HOME intent and prevent system launcher from activating.
  • WebView ↔ Native bridge — custom JS interface allows web content to invoke native device functions (set brightness, wake screen, launch external app) via postMessage protocol.
  • External app return — launching a third-party app via Intent and ensuring kiosk regains focus when user closes it requires ActivityLifecycleCallbacks monitoring.
  • patch-package reproducibility — React Native native module patches are committed as .patch files. npm ci + postinstall guarantees every build has identical native code regardless of machine.

Production Evidence

  • 🟢 Deployed and running live in a corporate production environment on physical Android tablet hardware.
  • Device fleet managed via ADB for deployment — tablets are enrolled in a managed deployment pipeline.
  • Remote config allows content and layout changes without pushing a new APK to physical devices.
  • Kiosk lock-down is permanent during operation hours — devices cannot be unlocked by end users.
  • This is not a proof-of-concept — real users interact with this system daily in a corporate setting.

Why React Native for an Android Kiosk?

  • React Native gives cross-platform UI with native module escape hatches for Android-specific APIs (Device Admin, Intent system, wake locks).
  • WebView integration is first-class — no need to build a custom WebView bridge from scratch.
  • TypeScript ensures type safety across the entire JS layer while native modules handle OS-level operations.

Engineering Principles

Applied consistently across all projects — not just stated, but demonstrated.

01 — Layering

Explicit, Enforced Layer Boundaries

Domain layers have zero knowledge of Data, Engine, or UI. Dependency directions are one-way. In GlowStudio AI and Verified AI, this is enforced at compile time through module visibility — Domain code cannot import a concrete repository class.

02 — AI Trust

AI Output is Untrusted Input

AI-generated content is always treated as untrusted data requiring independent verification. Verified AI cross-checks every AI math solution with SymPy. AI provider adapters are isolated behind ports — no business logic depends on a specific model or provider.

03 — Determinism

Deterministic, Testable State

Pure reducers and state machines produce the same output for the same input, always. Block Blast's GameReducer, Verified AI's domain invariants, and FitGen's Bloc states are all deterministic. This is what makes complex systems testable at scale.

04 — Honesty

No Fake Success

Systems must report honest failure states with explicit reason codes. MocapExpo never produces a BVH artifact from a failed dual-camera solve — missing_calibration, missing_sync, and primaryCameraFallbackUsed are always truthful and always visible.

05 — Security

Secrets Never in Source

API keys, credentials, and licensed model assets never enter version control. --dart-define, .env files, password managers, and S3 signed URLs enforce this consistently across every project in this portfolio.

06 — Documentation

Architecture Decisions are Written Down

Verified AI carries 45+ canonical documentation files and 4 formal ADRs. Why PostgreSQL over Firestore, why modular monolith over microservices — these decisions are documented with rationale so future maintainers don't repeat them from scratch.

07 — Offline First

Device-Local When Appropriate

GlowStudio AI runs all ML inference on-device — zero network dependency for core features. Seyir Kiosk operates on managed hardware without cloud dependency for basic kiosk function. Users shouldn't pay for uptime you don't control.

08 — Minimal Surface

Minimal External Dependencies

GlowStudio AI has zero third-party SDK dependencies in its app target. Verified AI's iOS app communicates only with the Spring Boot API. External dependencies are evaluated for necessity, not convenience — every third party is a future maintenance obligation.

09 — Observability

Structured Quality Metrics & Audit Trails

Systems produce structured quality reports, typed analytics, and explicit status fields. MocapExpo's 11-field quality_report_json, GlowStudio's BeautyQA pixel IoU gates, and Block Blast's Fastlane preflight scripts all create observable, auditable quality signals.
